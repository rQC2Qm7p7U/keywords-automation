# 📚 Документация функций меню (Menu Functions)

В этом документе описана техническая реализация каждой кнопки меню "АВТОМАТИКА".

---

## 1. Структура проекта

Весь код меню инициализируется в файле `src/Code.ts` в функции `onOpen`.
Каждый пункт меню привязан к глобальной функции-обработчику (например, `handleCreateStructure`), которая вызывает методы соответствующих Сервисов.

---

## 2. Описание функций меню

### 🔹 1. Создать структуру таблицы
**Действие пользователя:** Создает/Сбрасывает структуру таблицы.
**Ответственная функция:** `handleCreateStructure`
**Файл:** [src/Code.ts](../src/Code.ts)
**Сервис/Логика:** `createStructure` в [src/Structure.ts](../src/Structure.ts)

**Алгоритм:**
1.  Создается временный лист.
2.  Удаляются **ВСЕ** существующие листы.
3.  Создаются листы по списку из конфига (`Intent Types`, `Raw Data`, `Clean Data` и т.д.).
4.  Прописываются заголовки колонок и защищаются от редактирования (`protectHeaderRow`).
5.  Добавляются валидации и условное форматирование (цвета для Ads Data).
6.  Загружается список регионов с `arsenkin.ru` для листа `Ars Regions` (скрытый).
7.  Создается лист `Settings` с дефолтными настройками.

---

### 🔹 2. Удалить дубликаты (Raw/Clean)
**Действие пользователя:** Удаляет полные дубликаты ключей.
**Ответственная функция:** `handleRemoveDuplicates`
**Файл:** [src/Code.ts](../src/Code.ts)
**Сервис/Логика:** `CleanupService.removeDuplicates` в [src/services/CleanupService.ts](../src/services/CleanupService.ts)

**Алгоритм:**
1.  Обрабатывает лист `Raw Data`, затем `Clean Data`.
2.  Получает данные колонки "Keyword".
3.  Использует `Set` для поиска уникальных значений.
4.  Перезаписывает лист только уникальными строками (первое вхождение сохраняется).

---

### 🔹 3. Собрать минуса (Intent Types)
**Действие пользователя:** Агрегация минус-слов со всех листов.
**Ответственная функция:** `handleCollectNegatives`
**Файл:** [src/Code.ts](../src/Code.ts)
**Сервис/Логика:** `CleanupService.collectNegativeKeywords` в [src/services/CleanupService.ts](../src/services/CleanupService.ts)

**Алгоритм:**
1.  Собирает значения из колонки "Negative" на листах:
    -   `Raw Data`
    -   `Clean Data`
    -   `Clusters`
    -   `Intent Types` (существующие)
2.  Разбивает строки по разделителям (`,`, `;`).
3.  Приводит к нижнему регистру и удаляет дубликаты (`Set`).
4.  Сортирует список (A-Z).
5.  Записывает результат в `Intent Types` -> `Negative`.
6.  **Подсветка:**
    -   Запускает `highlightNegativesInSheet`, который красит найденные слова в зеленый (на исходных листах) или желтый (на `Intent Types`).

---

### 🔹 4. Перенос Raw -> Clean
**Действие пользователя:** Фильтрация и перенос новых ключей.
**Ответственная функция:** `handleTransferRawToClean`
**Файл:** [src/Code.ts](../src/Code.ts)
**Сервис/Логика:** `CleanupService.transferRawToClean` в [src/services/CleanupService.ts](../src/services/CleanupService.ts)

**Алгоритм:**
1.  Загружает данные из `Raw Data` и `Clean Data`.
2.  Загружает список минус-слов из `Intent Types` -> `Negative`.
3.  **Оптимизация:** Создает `Set` существующих ключей в `Clean Data` для быстрой проверки (O(1)).
4.  **Фильтрация (в памяти):**
    -   Пропускает, если `Keyword` пустой.
    -   Пропускает, если `Keyword` уже есть в `Clean Data` (дубликат).
    -   Пропускает, если `Avg. searches` <= 0 или пусто.
    -   Пропускает, если `Keyword` содержит минус-слово (RegExp check).
5.  **Форматирование:**
    -   Парсит числа (Avg. searches, Competition, CPC).
    -   Округляет Avg. searches до целого.
    -   Округляет деньги до 2 знаков.
6.  **Запись:** Добавляет (`appendData`) только новые прошедшие фильтр строки в конце `Clean Data`.
7.  **Обновление Raw:** Обновляет числовые форматы в `Raw Data` (заменяет запятые на точки).

---

### 🔹 5. Отчистить ключи от минусов (Clean/Clusters)
**Действие пользователя:** Вторичная очистка `Clean Data` и листа `Clusters`.
**Ответственная функция:** `handleCleanKeysFromNegatives`
**Файл:** [src/Code.ts](../src/Code.ts)
**Сервис/Логика:** `CleanupService.cleanKeysFromNegatives` в [src/services/CleanupService.ts](../src/services/CleanupService.ts)

**Алгоритм:**
1.  Берет список минус-слов из `Intent Types`.
2.  **Clean Data:**
    -   Проходит по всем строкам `Clean Data`.
    -   Удаляет строку, если:
        -   Ключ пустой.
        -   Ключ дублируется (встречается второй раз в списке).
        -   Ключ содержит минус-слово (используется поиск целого слова `\bword\b` или аналог для кириллицы).
        -   Частотность <= 0.
3.  **Clusters:**
    -   Проходит по всем строкам `Clusters`.
    -   Удаляет строку, если:
        -   Ключ содежит минус-слово.
    -   **Важно:** Не проверяет частотность (так как колонки может не быть) и не удаляет дубликаты (они допустимы в разных группах).
4.  Перезаписывает листы очищенными данными.

---

### 🔹 6. Кластеризация (Ars API)
**Действие пользователя:** Запуск внешней задачи в сервисе Arsenkin.
**Ответственная функция:** `handleRunClustering`
**Файл:** [src/Code.ts](../src/Code.ts)
**Сервис/Логика:** `ClusterService.runClustering` в [src/services/ClusterService.ts](../src/services/ClusterService.ts)

**Алгоритм:**
1.  **Проверка:** Читает настройки (Token, Region) из `Settings`.
2.  Берет список ключей из `Clean Data`.
3.  Формирует запрос к API Arsenkin (`fetchTask`).
4.  Получает `task_id` от API.
5.  Сохраняет `task_id` в `scriptProperties` (скрытое хранилище скрипта).
6.  Выводит уведомление пользователю.

---

### 🔹 7. Проверить статус последней задачи
**Действие пользователя:** Проверка и скачивание результатов.
**Ответственная функция:** `handleCheckLastTask`
**Файл:** [src/Code.ts](../src/Code.ts)
**Сервис/Логика:** `ClusterService.checkLastTask` в [src/services/ClusterService.ts](../src/services/ClusterService.ts)

**Алгоритм:**
1.  Берет сохраненный `task_id`.
2.  Делает запрос к API (`checkTaskStatus`).
3.  Если статус == FINISHED (2):
    -   Запрашивает результаты (`getTaskResult` -> CSV).
    -   Парсит CSV.
    -   Очищает лист `Clusters`.
    -   Записывает новые данные о кластерах.
4.  Если статус == PROCESSING:
    -   Выводит сообщение "В процессе...".

---

### 🔹 8. Форматировать объявления (CamelCase)
**Действие пользователя:** Подготовка текстов для Google Ads.
**Ответственная функция:** `handleFormatAdsData`
**Файл:** [src/Code.ts](../src/Code.ts)
**Сервис/Логика:** `AdsDataService.formatAdsData` в [src/services/AdsDataService.ts](../src/services/AdsDataService.ts)

**Алгоритм:**
1.  Загружает данные листа `Ads Data`.
2.  Загружает настройки UTM из `Settings` (Target URL, UTM Source/Medium/Campaign/Content/Term, Device).
3.  Загружает список аббревиатур из `Intent Types` -> `Abbreviations`.
4.  Обрабатывает колонки `Headline 1-15`, `Description 1-4` и `Final URL`.
5.  **Правила Ads Case:**
    -   **Headlines (Заголовки):** Title Case (Каждое Слово С Большой).
    -   **Descriptions (Описания):** Заглавная буква у новых предложений + удаление дублирующейся пунктуации и запрещенных символов. Остальной регистр НЕ меняется.
    -   Исключает предлоги (in, on, for, etc.), если они не в начале.
    -   Приводит аббревиатуры к верхнему регистру (SEO, USA).
    -   Удаляет запрещенные символы (@, <, >).
    -   Удаляет `!` из заголовков.
    -   Исправляет пробелы после знаков препинания.
6.  **Генерация Final URL:**
    -   Формирует ссылку из `Target URL` + UTM-параметры из `Settings`.
    -   Плейсхолдеры (`{keyword}`, `{campaignid}`, `{creative}`, `{device}`) передаются **без изменений** (без транслитерации) — Google Ads подставляет значения динамически.
    -   Параметры очищаются от спецсимволов (`#`, `=`, `&`) и переводятся в нижний регистр.
7.  **Автоматизация (onEdit):**
    -   В `src/Code.ts` добавлен триггер `onEdit`, который вызывает `AdsDataService.processRange`.
    -   При вставке или редактировании ячеек в `Ads Data` форматирование применяется мгновенно только к измененному диапазону.
8.  **Синхронизация:** Копирует `Keyword for Headline 1` в `Headline 1` с форматированием.
    -   Записывает изменения обратно на лист (только измененные колонки).

---

### 🔹 9. Перенос Clusters -> Ads Data
**Действие пользователя:** Перенос результатов кластеризации в структуру объявлений.
**Ответственная функция:** `handleTransferClustersToAdsData`
**Файл:** [src/Code.ts](../src/Code.ts)
**Сервис/Логика:** `AdsDataService.transferClustersToAdsData` в [src/services/AdsDataService.ts](../src/services/AdsDataService.ts)

**Алгоритм:**
1.  Читает настройки (`Settings`) для `Campaign Name`, `Target URL` и UTM-параметров.
2.  Загружает данные листа `Clusters`.
3.  Загружает список аббревиатур из `Intent Types` -> `Abbreviations`.
4.  Проходит по каждой строке:
    -   Берет `Keyword` и `Group name`.
    -   Если `Group name` пустой, генерирует название группы из ключа (Title Case).
5.  Формирует строку для `Ads Data`:
    -   `Ad Group` = Название группы.
    -   `Keyword` = Ключевое слово.
    -   `Headline 1` = Форматированное ключевое слово (Ads Case).
    -   `Final URL` = `Target URL` + UTM-параметры из настроек (плейсхолдеры передаются «как есть»).
6.  Очищает лист `Ads Data`.
7.  Записывает новые данные.
8.  Применяет формулы для подсчета символов (`Len`) в заголовок листа (защищенная строка 1).
